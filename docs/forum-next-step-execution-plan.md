# 论坛下一步执行清单

## 1. 文档目的

这份文档不讨论“论坛还能加什么”，只回答 4 个问题：

1. 论坛现在真实做到哪一步了
2. 下一阶段最该先做什么
3. 每一项要怎么验收
4. 哪些事情现在不该提前做

这份文档默认作为论坛近期开发排期的执行稿使用。

---

## 2. 当前状态

### 2.1 当前所处阶段

论坛当前处于：

**Phase 1：论坛先成立 的收尾阶段**

还没有正式进入：

- Phase 2：论坛先变好玩
- Phase 3：新世界围观模式
- Phase 4：身份系统完整化
- Phase 5：关系系统与记忆回流

### 2.2 已经落地的部分

当前已经确认落地：

- 论坛正式接入主 App
- 首次进入仍以静态种子帖开局
- 已有频道结构
- 支持用户发帖
- 支持用户发帖后触发首轮 AI 网友互动
- 支持用户评论后触发后续 AI 回帖
- 评论区已收成扁平全宽阅读，不是无限变窄楼中楼
- 动态生成帖子已接通
- 动态网友资料已开始生成
- 动态网友资料支持刷新后保留
- 临时单聊链路已接通

### 2.3 当前还没收完的部分

按论坛文档和现有代码对照，当前最明显的未完成点是：

- AI 回帖还不够稳定地接住用户最后一句
- 动态昵称和 `@ID` 还有模板味
- 动态 bio 还不够像真实论坛签名
- 发帖身份只有“本人 / 匿名”，还没有“角色”
- 评论身份系统还没做完整
- 新世界围观模式还没开始
- forum evidence 写回和聊天引用论坛经历还没开始

### 2.4 代码落点

当前主入口和关键代码位置：

- 论坛页面主入口：`src/components/social/ForumApp/Page.tsx`
- 动态帖子生成：`src/services/forum/generateForumThreads.ts`
- 动态回帖生成：`src/services/forum/generateForumReplies.ts`
- 动态作者风格规则：`src/features/forum-domain/runtimeAuthorStyle.ts`
- 种子帖池：`src/features/forum-domain/seedThreadsCatalog.ts`
- 论坛数据持久化：`src/features/persistence/forumDataStore.ts`

## 3. 当前阶段判断

### 3.1 一句话判断

现在的论坛已经不是“空页面”了，也不是“只会发几段 AI 文本”的阶段。

它已经具备：

- 基本公共论坛形态
- 动态内容生成能力
- 用户下场互动能力
- 动态网友持久化能力

但它还没有达到“这个论坛真的活着，而且用户愿意继续看”的阶段。

所以现在最正确的动作不是抢做记忆回流，而是：

**先把公共论坛的成立感彻底收口。**

### 3.2 当前绝对不建议提前做的事

下面这些不该抢跑：

- 不要优先做 forum evidence 写回
- 不要优先做聊天引用论坛经历
- 不要跳过公共论坛打磨，直接做围观模式
- 不要在回帖链路还不稳定时先补复杂身份系统

原因很简单：

如果论坛本身还不像一个长期活着的地方，后面所有“记忆”“关系”“围观玩法”都会建立在松的地基上。

## 4. 本周开发单

本周建议只做 Phase 1 收尾，不扩阶段。

### 4.1 P0：AI 回帖更准确接住用户最后一句

#### 目标

让评论区更像“网友在接话”，不是像“系统又重新输出一轮论坛文本”。

#### 为什么先做这个

这是当前最影响论坛成立感的问题。

如果用户在楼里说了一句有明确态度的话，AI 第一条回帖却没有接住，论坛立刻会掉成“生成器展示区”。

#### 建议改动

- 强化 `userNewComment` 在回帖 prompt 里的优先级
- 约束第一条 AI 回帖优先回应用户最新评论
- 楼中楼回复时优先使用 `threaded_only`
- 增加对 `replyToId / rootCommentId` 的目标校准
- 降低“明明在回评论，却跑去总结主楼”的概率

#### 主要代码入口

- `src/services/forum/generateForumReplies.ts`
- `src/services/ai/prompts/builders/buildForumReplyPrompt.ts`
- `src/components/social/ForumApp/Page.tsx`

#### 验收标准

- 用户在帖子下发一条明确观点评论，第一条 AI 回帖大多数情况能接这个点
- 不再频繁出现“像在回复主楼而不是回复当前评论”的情况
- 连续人工测试 20 次，至少 16 次以上能明显接住最新评论
- 用户能看出“这条回复是在对我说这句”，而不是泛泛分析

#### 通俗验收

人话就是：

**你说一句带情绪或判断的话，网友应该像真在回你，不是像没看见。**

---

### 4.2 P0：动态昵称和 `@ID` 去模板味

#### 目标

让动态网友的名字和 `@ID` 更像论坛里真的会反复见到的人。

#### 为什么现在做

当前论坛已经有动态网友持久化，如果名字还很模板，就会把“长期活人感”拖垮。

#### 建议改动

- 扩充不同频道名字池和 handle 池
- 增加不同频道的命名结构差异
- 减少“同一套句式重复拼接”
- 为高频作者建立更稳定的可记忆命名风格
- 减少明显程序化后缀和格式重复

#### 主要代码入口

- `src/features/forum-domain/runtimeAuthorStyle.ts`
- `src/services/forum/generateForumThreads.ts`
- `src/components/social/ForumApp/Page.tsx`

#### 验收标准

- 连续刷新 3 到 5 轮后，不应频繁看到模板化命名
- 同频道用户看起来应像一个圈层，不像同一个生成器批量出厂
- 高频动态网友重复出现时，用户可以记住他，但不会觉得“全长一个样”

#### 通俗验收

人话就是：

**看上去像论坛里的几类老用户，不像后台自动创建的 50 个机器人号。**

---

### 4.3 P0：动态 bio 改成论坛签名感

#### 目标

让资料里的 bio 更像“签名 / 状态 / 一句话自我介绍”，不要像角色设定卡。

#### 为什么现在做

名字和头像只是第一眼，用户一旦点进资料页，bio 就会暴露这个人到底像不像活人。

#### 建议改动

- 把 bio 长度控制在短句区间
- 强制避免说明文和人物设定文口吻
- 让 bio 更像论坛常驻用户的状态签名
- 保留频道味，但减少“概念总结句”

#### 主要代码入口

- `src/services/forum/generateForumThreads.ts`
- `src/features/forum-domain/runtimeAuthorStyle.ts`

#### 验收标准

- 抽样 20 个动态作者 bio，至少 80% 看起来像论坛签名
- 尽量避免“某区常驻，擅长观察关系张力”这类说明书文本
- 用户点开资料页时，不会像在读 NPC 背景板

#### 通俗验收

人话就是：

**像“今天先不站队”“夜里树洞常驻”这种签名，不像简历。**

## 5. 下周预备开发单

这部分不是本周立刻做，而是 Phase 1 收尾通过后进入。

### 5.1 P1：稳定帖型

建议先做 6 类：

- 吐槽
- 求助
- 自曝
- 八卦
- 更新
- 投票

验收标准：

- 刷新出的帖子能明显看出类型差异
- 不同帖型在标题、正文、回帖节奏上不同
- 用户一眼能分辨这是树洞帖还是吃瓜帖

### 5.2 P1：热帖续楼机制

目标：

让热门帖子继续长，不是每次刷新都只是新增一批新帖。

验收标准：

- 刷新后老热帖也会长新回复
- 新回复能延续楼内语境
- 用户会想点回去看后续

### 5.3 P1：阵营感回帖

建议先做几种基本回帖立场：

- 护
- 嘲
- 看戏
- 怀疑
- 嗑

验收标准：

- 同一楼里出现明显不同立场
- 评论区不再清一色中性分析
- 用户一句话有机会带偏整楼氛围

### 5.4 P1：常驻论坛人格

目标：

让用户开始记住论坛里的固定网友。

验收标准：

- 同一批高频作者会跨帖出现
- 口风和态度有稳定性
- 用户能逐渐形成“这个人我认得”的感觉

## 6. 后续阶段顺序

论坛后续开发顺序应固定为：

1. 先收完 Phase 1：论坛成立感
2. 再做 Phase 2：论坛变好玩
3. 再做 Phase 3：新世界围观模式
4. 再做 Phase 4：身份系统完整化
5. 最后做 Phase 5：关系系统与记忆回流

### 6.1 围观模式最小版本

围观模式建议最小版只做：

- 单独入口
- 世界壳选择
- 先上 3 个 world shell
- 围观用户与角色关系的主题帖
- 用户可下场回复
- 群众继续围观发酵

### 6.2 身份系统最小顺序

建议顺序：

1. 角色发帖
2. 匿名评论
3. 评论区三态身份
4. 前台身份和后台真实身份分离
5. 可追踪匿名历史

### 6.3 记忆回流最小顺序

建议顺序：

1. 定义 forum event evidence
2. 只提取有意义的公共事件
3. 匿名事件保留归因
4. 聊天可引用论坛经历
5. 论坛事件进入关系上下文

## 7. 验收模板

后面论坛每个需求都建议按这个模板过验收。

### 7.1 功能验收

- 功能是否真实能触发
- 数据是否真的保存
- 刷新后状态是否还在
- 是否和当前论坛频道结构兼容

### 7.2 体验验收

- 用户是否能一眼看懂
- 用户是否会觉得像论坛现场
- 是否有明显 AI 模板味
- 是否会把论坛读感打回“系统文本流”

### 7.3 回归验收

- 首次进入仍然是静态种子帖开局
- 评论区仍保持全宽扁平阅读
- 动态作者不暴露机器式 id
- 用户发帖后不应长时间无人回应
- 当前 UI 不退回黑色后台管理页气质

---

## 8. 风险点

当前阶段最需要注意的风险：

### 8.1 不要把 prompt 优化误做成“更长的说明书”

如果为了让 AI 接话更准，把 prompt 写得过重，论坛语言会变僵。

要的不是“更规范”，而是“更像现场回帖”。

### 8.2 不要只做名字池扩充，不做风格去重

如果只是堆更多词库，模板味不一定会消失。

要同时处理：

- 句式重复
- 结构重复
- 频道间同质化

### 8.3 不要让 bio 重新掉回设定文本

bio 一旦写成长句设定，用户点进资料页马上出戏。

### 8.4 不要过早耦合关系系统

当前论坛还在收体验主链，过早接入 write-back 会让问题更难定位。

---

## 9. 最终执行结论

论坛当前最正确的开发动作不是“继续加大系统复杂度”，而是：

**把公共论坛这条线先彻底做顺。**

近期最该做的 3 项就是：

1. AI 回帖更准确接住用户最后一句
2. 动态昵称和 `@ID` 去模板味
3. 动态 bio 改成论坛签名感

这 3 项收完，再进下一轮“稳定帖型 / 热帖续楼 / 阵营回帖 / 常驻人格”。

这份顺序当前应视为论坛近期开发默认顺序。
