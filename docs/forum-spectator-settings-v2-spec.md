# 镜间设置补充规格 v2

## 目标

把镜间当前单一的“对象”收成一套更清楚的目标模型，解决下面几件事：

1. 现在的“对象”更像一个混合字段，不够表达多角色关系线
2. 用户想讨论的不一定只是 `用户 x 单角色`
3. 用户在不同角色面前可能有不同身份，镜间需要能读取到这层差异

这份规格只定义设置结构和生成输入边界，先不要求本轮立刻把全部 UI 和生成链一次做完。

---

## 一、对象改名与拆分

### 1.1 结论

镜间设置里的“对象”不再继续作为一个混合入口使用，而是拆成两栏：

- `用户栏`
- `角色栏`

### 1.2 规则

- `用户栏`决定“围观者现在在看用户的哪个身份”
- `角色栏`决定“围观者现在在看哪些角色参与这条关系线”
- `料头`继续只管内容发酵点
- `帖型`继续只管结构

### 1.3 通俗意思

不是再手写一个“林然 x 张白”对象串。

而是改成：

- 先选“用户现在是谁”
- 再选“这条线里有哪些角色”

最后系统自己拼成：

- `用户 x 张白`
- `用户 x 张白 x 沈星回`
- `用户(面具A) x 张白 x 测试`

---

## 二、用户栏

### 2.1 作用

用户栏不是再选一次“对象名”，而是选“这次镜间围观的是用户的哪个身份版本”。

### 2.2 第一版来源

用户栏第一版至少支持：

- 默认用户本人
- 单聊里已有的可用面具

### 2.3 面具规则

- 面具读取来源是用户侧已有 `Mask`
- 镜间只读取“当前可用的用户身份滤镜”
- 面具属于用户，不属于角色
- 面具只能影响“围观者怎么看用户”
- 面具不能改写角色本体

### 2.4 通俗意思

这不是给角色换皮，而是让镜间知道：

- 这次别人讨论的你，是普通的你
- 还是“上班身份的你”
- 还是“测试身份的你”
- 还是“某个角色面前那套特殊身份的你”

---

## 三、角色栏

### 3.1 作用

角色栏从现在的“已选角色列表”升级为真正的关系目标栏。

### 3.2 基本规则

- 角色支持多选
- 选一个角色时，目标等价于：`用户 x 角色`
- 选多个角色时，目标等价于：`用户 x 角色1 x 角色2 ...`

### 3.3 角色关系位

多角色时需要支持角色位权重：

- `主角色`
- `副角色`
- `平角色`

### 3.4 角色位含义

- `主角色`：这条镜间楼主要围着谁转
- `副角色`：这条线里被重点带到，但不是绝对中心
- `平角色`：多人一起在场，关系权重接近

### 3.5 生成约束

- 如果存在主角色，生成时优先围绕主角色展开
- 副角色更多承担拉扯、对照、插入、站队变化
- 平角色更适合多人同场、修罗场、并列误读、围观混战

### 3.6 通俗意思

不是简单“多选几个名字”。

而是要表达：

- `用户 x 张白`
- `用户 x 张白(主) x 沈星回(副)`
- `用户 x 张白(平) x 测试(平)`

这样模型才能知道该把谁当中心、谁当陪衬、谁是并列线。

---

## 四、和现有字段的关系

### 4.1 新分工

- `用户栏`：决定用户以什么身份被讨论
- `角色栏`：决定哪些角色进入这条关系线
- `料头`：决定楼里在发酵什么内容
- `帖型`：决定帖子结构
- `小短文`：只决定片段帖内部的文段味

### 4.2 明确禁止

- 不要再让“对象”同时承担用户、角色、关系名三种职责
- 不要把面具混进角色栏
- 不要把料头当对象
- 不要把小短文当独立帖型

---

## 五、建议数据模型

当前 `ForumSpectatorSettings` 后续建议从：

- `subjectName`
- `selectedCharacterIds`

逐步演化为更结构化的目标配置，例如：

```ts
type ForumSpectatorTargetRole = 'primary' | 'secondary' | 'equal';

type ForumSpectatorTargetCharacter = {
  characterId: string;
  role: ForumSpectatorTargetRole;
};

type ForumSpectatorUserSlot = {
  mode: 'self' | 'mask';
  maskId?: string;
};
```

后续镜间设置层建议新增：

```ts
type ForumSpectatorSettingsV2 = {
  userSlot: ForumSpectatorUserSlot;
  targetCharacters: ForumSpectatorTargetCharacter[];
};
```

旧字段可以先保留兼容，不要求一步删掉。

## 六、验收标准

### 6.1 设置层

- 用户能明确区分“用户栏”和“角色栏”
- 角色栏支持多选
- 多角色时能设置主 / 副 / 平
- 用户栏能看到可用面具

### 6.2 生成层

- 选一个角色时，镜间结果稳定像 `用户 x 单角色`
- 选两个角色时，镜间结果不再退回成单角色楼
- 指定主角色后，生成内容明显更围绕主角色
- 指定用户面具后，围观语气会反映“别人正在按这层身份理解用户”

### 6.3 体验层

- 用户不需要自己手写“对象串”
- 多角色线终于能被正式表达
- 面具不再只存在于私聊，而是能进入镜间围观语境

---

## 七、和第一层的关系

这条需求已经属于第一层剩余项的一部分，因为它直接影响：

1. 镜间设置是否真的能控制生成
2. 镜间是否能从“单角色围观”升级到“关系线围观”
3. 面具这条用户身份层是否能进入镜间语境

所以它不是后面的锦上添花，而是镜间设置层继续收口时必须纳入的正式需求。
