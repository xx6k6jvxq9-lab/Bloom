# 梦境 App 全量详细方案

## 1. 产品定义

`梦境` 不是聊天附属页、也不是普通小游戏入口，而是一个**独立手机应用**。

它的目标不是记录梦，而是：

1. 让用户进入一个可被选择、可被生成、可被角色影响的平行世界
2. 在这个世界里围绕剧情、关系、动作和情绪推进一场完整梦局
3. 在结尾产出一张具有作品感、可截图分享的终页
4. 只把轻微余响带回现实聊天，不污染主线

一句话定义：

> 梦境 App 是一个以“梦域、剧情推进、角色语境、轻动作互动、结局终页、轻回流”为核心的独立互动应用。

---

## 2. 为什么要做成独立 App

梦境不应该长成：

1. 聊天里的一个小弹窗
2. 功能中心下的一个普通卡片
3. 一段随手生成的剧情试玩

而应该长成：

1. 底部或桌面可直接进入的独立应用
2. 一打开就有“沉进去”的氛围
3. 拥有独立的节奏、页面层次和结尾机制
4. 能承载长局、世界观、角色主导和后续扩展

这也是它和 `情侣空间`、`听歌` 同级的原因。

---

## 3. 产品核心结构

梦境 App 的骨架由 4 层构成：

### 3.1 梦域

回答：这是一场什么梦。

它决定：

1. 世界类型
2. 风格边界
3. 角色是否深接语境
4. 剧情生成的语气和世界规则

### 3.2 梦线

回答：这场梦怎么往前走。

它决定：

1. 当前局的冲突
2. 每轮推进方向
3. 结局类型
4. 节奏和转折

### 3.3 梦触

回答：用户在梦里怎么与世界互动。

它决定：

1. 用户不是只看文本
2. 用户能通过选择、拖动、长按等动作推进剧情
3. 角色会对用户动作而不是单纯选项产生反应

### 3.4 余响

回答：梦结束后现实里留下什么。

它决定：

1. 梦不会白玩
2. 但梦也不会把现实聊天污染掉
3. 回流只保留“影响”，不保留整段过程

---

## 4. 梦域体系

当前梦域体系定为 4 类。

### 4.1 众生梦

定位：公共幻想世界。

适合：

1. 大热小说题材
2. 大众熟悉的幻想世界
3. 高可玩 roleplay

常见方向：

1. 西方魔幻
2. 古代王朝
3. 未来科技
4. 末日废土
5. 规则怪谈
6. 兽人世界
7. 哨向
8. ABO
9. 星际

特点：

1. 更偏题材体验
2. 更容易理解
3. 更适合一键入梦和自定义入梦
4. 可只吃轻量角色人设层，不必重接统一语境层

### 4.2 歧境梦

定位：半架空世界。

定义：看起来像现实，但规则从某个地方开始歪掉。

例子：

1. 时间倒流的学校
2. 影子先开口的城市
3. 只停不存在站点的列车
4. 雨往上落的街道
5. 电梯通向情绪楼层

特点：

1. 最有梦味
2. 最容易做出辨识度
3. 很适合中短篇梦局
4. 更适合“异常规则 + 关系推进”混合

### 4.3 同梦域

定位：你和角色共同长出来的双人世界。

它不是：

1. 角色自己的私密世界
2. 普通公共题材世界

它是：

1. 因为你和这个角色的关系而生成的世界
2. 世界本身就是关系的投影

适合：

1. 暧昧
2. 拉扯
3. 重逢
4. 试探
5. 错过
6. 双人任务

特点：

1. 最像这个产品自己
2. 最值得优先做
3. 适合轻接统一语境层

### 4.4 心隙梦

定位：进入角色内里的世界。

关键词：

1. 秘密
2. 执念
3. 防线
4. 旧记忆
5. 不肯说出口的部分

特点：

1. 不是普通题材体验
2. 是真正意义上的“进入他的梦”
3. 必须深接统一语境层
4. 适合后续角色入梦模式

## 5. 入梦方式

当前保留 2 条正式入口，1 条后续高级入口。

### 5.1 一键入梦

定位：最快开始一局梦。

流程：

1. 用户点击一键入梦
2. 系统随机生成一组合理标签
3. 展示本局梦的摘要
4. 用户确认进入

特点：

1. 快
2. 适合第一次体验
3. 适合高频反复打开

### 5.2 自定义入梦

定位：用户主动定制梦局。

流程：

1. 选梦域
2. 选基础标签
3. 可选细化标签
4. 确认本局摘要
5. 进入梦境

特点：

1. 参与感强
2. 适合有明确偏好的用户
3. 是梦境 App 的主要配置方式

### 5.3 角色入梦

定位：高级黑盒入口。

说明：

1. 用户先选角色
2. 其余设定大部分由角色自己决定
3. 用户进入后才逐步知道身份、阵营、关系位置

特点：

1. 黑盒感
2. 强角色感
3. 必须深接统一语境层

状态：

1. 当前为后续阶段重点功能
2. 第一版可先不落地完整实现

## 7. 轮次结构

梦境按“局”推进，而不是单页结束。

### 7.1 浅梦

1. 总轮数：`4-5轮`
2. 适合一次完整体验
3. 一局一结
4. 更像短篇梦局

### 7.2 深梦

1. 总轮数：默认 `20轮`
2. 分幕：`5轮一幕`
3. 用户每一幕结束后可以决定：
   - 继续沉入
   - 暂且醒来
   - 就此收束

### 7.3 深梦四幕

#### 7.3.1 入雾

轮次：1-5 轮

任务：

1. 定世界
2. 定身份
3. 定关系位
4. 定第一层异常

#### 7.3.2 失真

轮次：6-10 轮

任务：

1. 冲突扩大
2. 梦开始变形
3. 角色态度出现偏移
4. 用户开始看见“这场梦不只是表层”

#### 7.3.3 裂响

轮次：11-15 轮

任务：

1. 真相
2. 分歧
3. 站队
4. 关系失衡
5. 世界规则被揭开

#### 7.3.4 醒潮

轮次：16-20 轮

任务：

1. 收束
2. 反转
3. 坠落或靠近
4. 留白或未醒
5. 进入结局页

## 8. 梦触交互

### 8.1 第一版必做交互

#### 8.1.1 选择

用于：

1. 剧情分支
2. 态度表明

#### 8.1.2 拖动

用于：

1. 推门
2. 递交物品
3. 拉近距离
4. 移动物件

#### 8.1.3 长按

用于：

1. 稳定梦境
2. 叫住角色
3. 压住情绪

1. 滑动
2. 输入一句话

4. 节奏触发
5. 选择 + 动作混合

## 9. API 调用策略

梦境必须调 API，但不能每一步都重调用。

### 9.1 推荐调用层次

#### 9.1.1 开局生成

调用 1 次 API，生成：

1. 本局起始世界状态
2. 用户身份
3. 角色身份
4. 初始冲突
5. 当前场景描述
6. 初始候选动作

#### 9.1.2 每轮推进

每轮调用 1 次 API，生成：

1. 场景新状态
2. 角色回应
3. 下一轮动作候选
4. 当前轮情绪与关系变动

#### 9.1.3 关键节点

在重要分歧轮或每幕结尾轮再调用一次更重的生成：

1. 真相揭示
2. 关系偏移
3. 结局方向
4. 更强的文案张力

#### 9.1.4 结局生成

分为三段：

1. 结局标题：池子
2. 梦尾摘录：API
3. 篇名：API 或规则生成

### 9.2 不建议的调用方式

1. 每个按钮都调一次模型
2. 每个微交互都完整重生成
3. 每个梦域都深接完整记忆层
4. 让 API 自己决定所有产品结构

## 10. 统一语境层接入策略

### 10.1 总原则

统一语境层要接，但**按梦域深浅分层接**。

### 10.2 各梦域接入深度

#### 10.2.1 众生梦

建议：

1. 只接轻量角色人设层
2. 不深接完整关系与记忆

原因：

1. 它更偏题材体验
2. 太深接会把梦重新拉回现实聊天

#### 10.2.2 歧境梦

建议：

1. 轻接语境层
2. 保留角色风格和少量关系氛围

#### 10.2.3 同梦域

建议：

1. 轻接到中等深度语境层
2. 重点吃当前关系温度、最近互动、角色对用户的态度

#### 10.2.4 心隙梦

建议：

1. 深接统一语境层
2. 读取角色内在状态、短期摘要、长期记忆、关系投影、最近聊天余波

### 10.3 角色入梦

角色入梦是最应该深接统一语境层的模式。

它至少应读取：

1. core persona
2. expression style
3. relationship projection
4. short-term summary
5. long-term memory profile
6. recent chat window
7. recent moments
8. 当前时间段与状态

## 11. 轻回流机制

梦境结束后必须回流，但只能轻回流。

### 11.1 可以回流的内容

1. 一句梦后余响
2. 轻微关系温度变化
3. 少量称呼和语气漂移
4. 可选动态痕迹
5. 少量记忆痕迹

### 11.2 不回流的内容

1. 整场梦全文
2. 梦里完整世界设定
3. 全部 NPC 关系
4. 所有过程性对话
5. 梦中全部细节动作

### 11.3 原则

回流的是：

> 梦带来的影响

不是：

> 把梦完整搬回现实

---

## 12. 角色入梦模式

### 12.1 模式定义

角色入梦不是普通自定义变体，而是一条独立高级入口。

### 12.2 体验流程

1. 用户选择角色
2. 角色自己决定大部分标签
3. 用户进入后才逐渐知道：
   - 自己在梦里是谁
   - 角色在梦里是谁
   - 这局真正的冲突是什么
   - 阵营站位是什么

### 12.3 特点

1. 黑盒感
2. 强人设感
3. 强语境感
4. 比普通入梦更像“进入他的世界”

### 12.4 建议落位

1. 优先落在 `心隙梦`
2. 特殊情况下也可落在 `同梦域`

---

## 13. 结局系统

梦境的结局不是“结束提示”，而是一张完整终页。

### 13.1 结局页结构

1. `结局标题`
2. `梦尾摘录`
3. `——角色名`
4. `《梦局篇名》`

### 13.2 结局标题

要求：

1. 2-4 个字
2. 由池子提供
3. 统一气质
4. 避免 API 随机翻车

### 13.3 梦尾摘录

要求：

1. 不是短句
2. 不是总结
3. 不是系统说明
4. 是一段可截图分享的“书摘式结尾文案”

风格已另见：

- [dream-ending-generation-spec.md](/e:/小手机/Bloom/docs/dream-ending-generation-spec.md:1)

### 13.4 署名

格式固定：

`——角色名`

例如：

`——周既白`

### 13.5 梦局篇名

由这一局梦生成篇名，增强“作品感”。

例如：

1. `《雾港尽头》`
2. `《未曾停靠的月台》`
3. `《王城之后》`

## 14. UI 结构与视觉方向

### 14.1 UI 不是普通平铺卡片

梦境页面不能长成：

1. 普通设置页
2. 普通功能列表
3. 普通标签表单

### 14.2 目标体验

梦境 UI 要给用户的感受是：

1. 一层又一层
2. 沉进去
3. 像推开门
4. 像掉进更深的夜里

### 14.3 推荐层次

1. `封面层`
   - 大标题
   - 氛围背景
   - 入梦按钮
2. `梦域层`
   - 选择众生梦 / 歧境梦 / 同梦域 / 心隙梦
3. `标签层`
   - 基础标签与细化标签
4. `确认层`
   - 当前梦局摘要
5. `梦局层`
   - 正式剧情推进
6. `终页层`
   - 结局标题、梦尾摘录、角色名、篇名

### 14.4 视觉关键词

1. 夜色
2. 漂浮
3. 压深
4. 玻璃层
5. 缓慢推进
6. 仪式感

4. 完整深梦全量内容
5. 真图片生成
6. 今日梦签

## 20. 一句话总结

梦境 App 不是一个“新页面”，而是一条新的产品线。

它的目标是：

> 让用户和角色进入一场被世界观、关系张力、剧情驱动与动作交互共同支撑的梦局，并在结尾留下可分享的作品式终页，再让这场梦只以轻微余响回到现实。
