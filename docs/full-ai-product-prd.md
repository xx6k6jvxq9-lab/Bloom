# Bloom 完整产品 PRD

更新时间：2026-04-04
文档版本：V2026.04
文档定位：基于当前代码仓库的真实能力整理产品定义、范围、主线与后续优先级

## 1. 产品定义

### 1.1 一句话定义

Bloom 是一款以“手机桌面容器 + AI 角色互动 + 长期关系经营”为核心的沉浸式 AI 产品。

### 1.2 产品本质

Bloom 不是单点聊天工具，而是一个承载角色、关系、记忆和生活痕迹的 AI 手机。产品要让用户获得的不是单轮回复，而是：

- 角色持续存在感
- 关系连续性
- 内容沉淀感
- 空间拥有感

### 1.3 当前阶段

当前 Bloom 处于“主线能力已经成型，平台化底座持续补强”的阶段。

已经形成稳定主线：

- 手机桌面容器
- AI 单聊
- 多角色组织
- 动态系统
- 约会入口与场景
- 情侣空间
- 本地持久化

正在持续深化的主线：

- 角色边界与 OOC 治理
- 记忆分层
- 群聊场景输入
- 约会与情侣空间统一关系输入
- 主动内容引擎

## 2. 产品目标

### 2.1 总目标

让用户拥有一部可以长期使用、可以经营关系、可以沉淀记忆的 AI 手机。

### 2.2 当前版本目标

- 做稳聊天主链
- 让角色不只存在于聊天框
- 建立情侣空间作为深关系中枢
- 建立可恢复的本地长期数据层
- 让主动内容具备最小可用且可控的产品机制

### 2.3 非目标

当前版本不追求：

- 完整云端账号系统
- 多端实时同步
- 大规模真实社交网络
- 重型后端平台化
- 强商业化支付闭环

## 3. 目标用户

### 3.1 核心用户

#### A. AI 陪伴重度用户

关注稳定人设、长期记忆、情绪反馈和陪伴感。

#### B. 角色互动与世界观用户

关注多角色、多场景、一致性表达和世界感。

#### C. 关系经营型用户

关注约会、纪念、留言、情书、共笔、情侣空间等深关系能力。

#### D. 个性化空间用户

关注壁纸、图标、布局、聊天样式、全局 CSS 和“我的设备”感。

## 4. 用户问题

Bloom 主要解决以下问题：

- AI 像工具，不像关系对象
- 角色只在聊天框里出现，缺乏生活感
- 互动不能沉淀成长期资产
- 陪伴产品缺少用户拥有感
- 主动内容容易过火或失控

## 5. 产品价值

### 5.1 对用户

- 更强的沉浸感
- 更稳定的角色感
- 更连续的关系体验
- 更强的空间归属感

### 5.2 对产品

- 更高留存潜力
- 更高内容沉淀价值
- 更高差异化壁垒
- 更强的后续平台扩展能力

## 6. 当前产品范围

### 6.1 首页与手机容器

目标：建立设备感和统一入口。

当前能力：

- 桌面壁纸
- 图标摆放
- Dock
- 桌面组件
- 顶部导航栏
- 字体与布局自定义

关键价值：这不是单纯 UI 装饰，而是 Bloom 的产品心智入口。

### 6.2 主应用壳

目标：组织聊天、通讯录、动态、我的四大主入口。

当前能力：

- 主 Tab 切换
- 聊天列表
- 通讯录入口
- 动态入口
- 我的入口

### 6.3 AI 聊天系统

目标：作为核心关系入口，承载陪伴、推进和多模块触发。

当前能力：

- 单聊
- 群聊
- 流式回复
- 消息收藏、引用、转发、删除、分享
- 摘要生成
- 通话记录沉淀
- 与动态、约会、情侣空间、论坛等联动

产品规则：

- 回复需要稳定角色感
- 并发请求不能覆盖最新生成
- 聊天必须是多模块关系入口，而不只是文本生成壳

### 6.4 通讯录与角色组织

目标：把角色从 prompt 对象升级为系统联系人。

当前能力：

- 联系人列表
- 搜索与分组
- 新朋友入口
- 群聊管理
- 角色资料页
- 备注名显示

当前角色资料结构重点字段：

- `setting`
- `corePersona`
- `expressionStyle`
- `boundaryPack`
- `remarkName`
- `signature`
- `shortTermSummary`
- `longTermMemoryProfile`

### 6.5 动态系统

目标：提供聊天之外的公开生活痕迹。

当前能力：

- 动态发布
- 评论与回复
- 聊天命令触发发布
- 自动触发发布
- 动态评论回复生成

产品规则：

- 动态内容要像生活表达，不像系统通知
- 自动发布要克制，避免刷屏感

### 6.6 约会模块

目标：提供高沉浸、剧情化关系推进场景。

当前能力：

- 从聊天发起
- 进入独立约会场景
- 生成场景内容
- 会话记录保存
- 收藏与留存

产品规则：

- 约会必须明显区别于普通聊天
- 约会内容要更具场景感与叙事感

### 6.7 情侣空间

目标：承载 Bloom 的深关系经营能力。

当前能力：

- 按 partner 独立建立空间
- 情书
- 留言板
- 共同笔记
- 小账本
- 情侣动态
- 日历
- 纪念日
- 心情印章
- 归档中心
- 心动胶囊机
- 主动内容设置与手动检查

数据结构特征：

- `currentPartnerId`
- `spacesByPartnerId`

产品规则：

- 每个角色的关系空间必须独立
- 深关系内容要能沉淀、可归档、可回看
- 高风险主动内容不能直接无门槛写入

### 6.8 主动内容系统

目标：让角色从被动回复进化到有限主动参与。

当前能力重点集中在情侣空间：

- action settings
- cadence / opportunity / evidence level
- manual check
- auto check gate
- candidate 生成与打分
- `Auto / Draft / Confirm` 提交路径

当前支持的动作类型包括：

- 发情侣动态
- 写情书
- 留言板留言
- 写共同笔记
- 记录账本
- 回复情书
- 回复动态评论
- 回复留言板
- 对已有内容做反应

产品规则：

- 默认保守
- 用户可关闭
- 按风险分级
- 不为“显得亲密”而虚构关系事实

### 6.9 个性化系统

目标：增强设备拥有感和长期投入感。

当前能力：

- 全局壁纸
- 图标自定义
- 桌面组件
- 导航栏样式
- 字体与网格布局
- 聊天气泡与头像样式
- 动态卡片样式
- 全局 CSS 注入
- 主题导入导出

### 6.10 数据管理

目标：保证长期使用的可恢复性。

当前能力：

- 模块化导出
- 全量导出
- 模块化导入
- 全量导入
- 本地清空重置

### 6.11 生活化模块

目标：增强陪伴氛围和生活感，不让产品只剩聊天。

当前能力：

- 音乐
- 钱包
- 论坛
- 监控
- 小游戏

产品判断：这些模块当前主要服务世界感和设备感，不是独立商业化应用。

## 7. AI 产品底座

### 7.1 模型配置

当前支持：

- Gemini
- OpenAI 兼容接口

产品要求：

- 用户可在应用内切换配置
- 业务层不直接依赖 provider 细节

### 7.2 Runtime

当前已具备统一 runtime 能力：

- 非流式文本生成
- 流式文本生成
- SSE 兜底解析
- 响应清洗
- `<think>` 泄露内容过滤

### 7.3 Prompt 体系

当前已按场景拆分：

- chat
- groupChat
- dating
- moments
- momentCommentReply
- coupleSpace
- summary

产品判断：Bloom 的 prompt 已经从模板，进化为“场景行为规则层”。

## 8. 记忆与关系上下文

### 8.1 当前已落地

- 聊天摘要
- `shortTermSummary`
- `longTermMemoryProfile`
- `buildCharacterContext`
- `buildRelationshipProjection`
- `buildChatSceneInput`
- `buildGroupChatSceneInput`
- `buildDatingSceneInput`

### 8.2 当前产品意义

这说明 Bloom 已经不再是每个模块各自拼 prompt，而是在形成统一关系输入层。

### 8.3 当前不足

- 真正完整的 structured memory 还未正式落地
- recall 仍是轻量阶段
- couple-space 主链与 boundary/scene input 的统一接入仍在推进

## 9. 成功标准

当前阶段的产品成功，不以“功能数量”判断，而以以下标准判断：

- 用户能把 Bloom 视为一部 AI 手机，而不是聊天页
- 用户能感知角色在多个模块中的连续存在
- 关系内容能沉淀而不是每次归零
- 情侣空间能成为高留存、高投入模块
- 主动内容既能工作，又不越界

## 10. 当前主要风险

### 10.1 顶层装配仍然偏重

`src/App.tsx` 仍承担大量页面、状态和装配逻辑。

### 10.2 角色稳定性仍需继续治理

虽然已引入 `corePersona / expressionStyle / boundaryPack`，但场景接入仍在逐步收口。

### 10.3 记忆层还处于从“可用”向“可承重”演进的阶段

现有能力已足够支撑主线，但还不足以支撑未来更复杂的主动行为和更多生活模块。

### 10.4 产品文档过去存在过度理想化描述

当前版本必须坚持“以仓库真实能力为准”，避免把未落地能力写成既成事实。

## 11. 后续优先级

### P0

- 做稳聊天、群聊、约会、情侣空间的统一场景输入
- 继续做角色边界与 OOC 基础治理
- 做稳情侣空间主动内容主链

### P1

- 完整记忆分层
- 更稳定的 couple-space 执行与回流
- 更正式的时间感知与主动决策底座

### P2

- 论坛、更多生活模块接入统一关系与记忆底座
- 更强的多模态与平台化扩展

## 12. 结论

Bloom 当前最重要的产品判断不是“继续堆页面”，而是把已经出现明显差异化价值的主线做深：

- 手机容器
- 长期关系
- 情侣空间
- 记忆与上下文
- 可控主动内容

如果这些主线继续做稳，Bloom 会从“多模块 AI 手机”进一步进化成真正的“关系型 AI 平台”。
