# 梦尾摘录生成规范

> 总方案与梦域/轮次/标签/回流等完整设计，见 [dream-app-full-spec.md](/e:/小手机/Bloom/docs/dream-app-full-spec.md:1)

## 目标

梦境 App 的结局页不使用“短语录”结构，而使用可截图分享的结尾卡结构：

1. 结局标题
2. 梦尾摘录
3. `——角色名`
4. `《梦局篇名》`

其中：

1. 结局标题：走池子，2-4 个字
2. 梦尾摘录：调用 API 生成
3. 角色名：直接使用当前角色名
4. 梦局篇名：调用 API 生成，2-8 个字

## 输出结构

结局页中央文案固定为：

```text
<结局标题>

<梦尾摘录>

——<角色名>
《<梦局篇名>》
```

说明：

1. 结局标题独立显示，不混在正文里
2. 梦尾摘录是主体，不是对白，不是总结
3. 角色名固定显示为当前角色名，不生成假作者
4. 篇名是这局梦的名字，不是真实书名

## 梦尾摘录风格

梦尾摘录不是一句轻残响，而是一段“像文学作品结尾摘录”的文案。

必须满足：

1. 有书摘感、结尾感、留驻感
2. 不是聊天口语
3. 不是系统总结
4. 不是鸡汤文案
5. 不是解释梦局发生了什么
6. 适合单独截图分享

长度建议：

1. 35-90 字
2. 2-5 行排版为宜

## 学习案例

以下案例作为模型风格学习样本，不要求复写内容，但要求学习其“结尾摘录感”。

### 案例 1

```text
冬天会周而复始，
该相逢的人会再相逢。
所以，我们不必总惦记遗憾，
而是要学会期待。

——赫尔曼·黑塞
《克林索尔的最后夏天》
```

### 案例 2

```text
我在她的眼睛里读到，
我们原可以在一起白头偕老，
永远幸福的。

——陀思妥耶夫斯基
《被侮辱与被损害的人》
```

### 案例 3

```text
你追求的憧憬虽然到了手，
却在到手的一刹那间，
改变了面目。

——矛盾
《蚀》
```

### 案例 4

```text
为了让一切有个了结，
为了使我不感到那么孤独，
我还是希望我被处决的那天
有很多人来观看，
希望他们用仇恨的喊声来欢迎我。

——加缪
《局外人》
```

### 案例 5

```text
他转过身去；
眼睛看着远处那艘漂亮的巡洋舰，
让他们有时间镇定一下，
他等待着。

——威廉·戈尔丁
《蝇王》
```

### 案例 6

```text
日出未必意味着光明，
太阳也无非是一颗晨星而已，
只有在我们醒着时，
才是真正的破晓。

——梭罗
《瓦尔登湖》
```

## 模型必须学习的不是内容，而是以下特征

1. 文案像结尾摘录，不像状态文案
2. 句子有沉静的结束感
3. 允许有留白，但不故作玄虚
4. 可以有哲思，但不能像励志鸡汤
5. 允许带一点宿命、遗憾、醒悟、静默、偏执
6. 不要把剧情直接解释出来
7. 不要出现“你获得了某结局”“本局结束”这类系统表达

## 生成输入

调用 API 生成梦尾摘录时，输入建议固定为：

1. 梦域
2. 世界观
3. 题材母题
4. 关系张力
5. 剧情驱动
6. 情绪底色
7. 结局类型
8. 结局标题
9. 本局关键动作摘要
10. 当前角色名

## 生成约束

模型生成梦尾摘录时必须遵守：

1. 只输出正文，不输出标题
2. 不输出作者名
3. 不输出书名
4. 不输出引号
5. 不输出编号
6. 不解释结局类型
7. 不写成对用户说话
8. 不要用现代社交媒体腔调

## 梦局篇名生成规则

梦局篇名由 API 单独生成，要求：

1. 2-8 个字
2. 像章节名、篇名、梦名
3. 不要过度网文化
4. 不要直接复述标签

推荐风格：

1. 雾港尽头
2. 长夜余灯
3. 门后的潮声
4. 未醒之城
5. 失约之春

## 第一版实现建议

第一版采用以下组合：

1. 结局标题：池子
2. 梦尾摘录：API 生成
3. 角色署名：固定 `——角色名`
4. 梦局篇名：API 生成
5. 轻余响：规则回流

## 不做的事

第一版不做：

1. 用真实名家署名
2. 模仿具体作家文风
3. 生成过长段落
4. 生成现代鸡汤海报文案
5. 把整局剧情总结成说明文
